## Run receipt: preflight and target markers (retro #13357/#13435; CTO C0ALZJHGE49 thread 1794234970.206389, ts 1794578332.315349)
Extend the existing run receipt. Nothing here blocks or refuses a run: no new wrapper, gate or review chain, and setup and readiness checks are unchanged. Missing or unverified items are recorded as UNKNOWN or partial evidence.
- **Receipt fields.** Before the first action under test, write these receipt fields from the brief: `scenario` (name, or `manual (scenario adapter missing)`), `target_route` (the exact route/dialog the AC acts on), `target_context` (which tab/browser context performs each action), `storage_scope` (browser profile/storage per context, Convex deployment, QA R2 bucket scope) and `browser_contexts` (one row per context: id, tab, signed-in subject, profile/storage). A field the brief omits and you cannot read back from the owned box is `UNKNOWN`.
- **Read back before the affected scenario.** After readiness, read each field back from the live session (current URL/route, signed-in subject, storage) before the action under test and record `verified`, `UNKNOWN` or `MISMATCH` for it. The scenario still runs as briefed, and the existing precondition assertions in qa-brief are unchanged. Any UNKNOWN or MISMATCH field makes the capture PARTIAL evidence for the AC that depends on it, and the report names the field.
- **Same-user writer move.** The receipt records two INDEPENDENT browser contexts (separate profile/storage, so distinct per-browser ids) signed in as the SAME intended synthetic subject, read back before the move, with the starting writer and the target context named. Two tabs in one profile are one browser, so a capture of them is PARTIAL evidence for a different-browser or different-device AC.
- **Markers on the existing clip/trace.** For each action under test append a marker to the receipt: `t` (seconds from recording start; `elapsed_s` in `scenario.json`), context/tab, current route, action, observed outcome. qa-video-review maps AC steps to the video through these markers.
- **Partial evidence.** If the clip or trace never shows the target route/dialog or the target context at its marker, label the capture PARTIAL evidence in the report and name the missing marker. Do not cite it as full evidence for the AC.
