# Daily PM restart

**PM replacement goes ONLY through MoP `POST http://127.0.0.1:3100/slots/0/respawn` with `{"continue_session":true}`** (Rajiv, DM D0AMF0XE6TS thread 1793151634.784279, ts 1793164925.956469: "pm pane is supposed to restart through MoP. check the code once."; ts 1793165074.499419 "update it cliproxy."; ts 1793166747.066109). MoP runs RESTART_COMMANDS[0] = `launch-pm-cliproxy.sh --continue`, waits for boot and sends "continue"; the script then delivers the dated resume prompt via MoP `POST /slots/0/send`. A MoP 409 (busy / respawn in progress) = deferred, not an error, no retry. **Never `tmux respawn-pane` the PM directly.**

Source: Rajiv, 2026-10-27: "restart pm at 4 am in the morning. add it to the MoP, like the other notification. it should trigger a skill that does all this, preferably in a script. the dev slots can be restarted by just setting exit pending on it."

1. While processing this skill, run `~/.claude/scripts/pm/daily-pm-restart.sh` once. This is CHECKPOINT ONLY: it snapshots canonical obligations, slots and PRs into the dated 0400 resume file, updates MEMORY.md, and fsyncs the pending handoff bound to this PM owner/turn. It performs no cleanup, exit-pending request or replacement inside the active PM/helper tree. Then return from this skill/turn; do not run more tools, poll, launch a detached helper or invoke `--complete-on-idle` yourself. The EXISTING MoP debounced Stop/idle boundary owns that continuation outside Claude's tree, only with no queued work. It runs guarded cleanup, arms safe-point dev exits, and performs the pinned PM replacement once via MoP /slots/0/respawn. Use `--dry-run` for read-only inspection. Never interrupt or respawn a dev pane.
2. The new PM reads the resume file and current ledger, reconciles each listed background-agent owner with live work, and relaunches only stopped agents that still have open work. Preserve task evidence, branches and ownership; a person or slot owner is not an agent type. Do not duplicate a running or completed agent. If the original agent packet is unavailable, record that precise blocker rather than inventing its task.
3. After recovery, post ONE line to Rajiv's DM `D0AMF0XE6TS` with the resume path and any blocked relaunches using the existing slack-send.sh and a unique scratch input file. An idempotent `ALREADY_REQUESTED` result means finish recovery from the saved file, not force another restart.

The script is locked and durably checkpointed per IST date. Busy checkpointing pins the Claude owner without treating its own Bash/Python/ps descendants as quiescent; only the later effect phase requires proven idle, no queued work, an empty composer and NO tool descendants. That phase binds immutable pane/session/PID/process birth/checkout plus the saved SessionStart/UserPromptSubmit and work-event history; only the requesting Bash's completion and Stop may follow the checkpoint. A new prompt, successor or intervening tool prevents the old handoff. Full fresh identity/work checks remain after cleanup and immediately before replacement. The replacement is MoP's idle-gated /slots/0/respawn, which re-verifies pane identity itself. A fsynced attempted replacement is permanent even after timeout, lost response or exception: reconcile the pane and retained state; never clear intent or issue another kill automatically. Logs are `/tmp/daily-pm-restart-<date>.log`; state is `~/.claude/state/daily-pm-restart-<date>.json`. A failed snapshot, pointer validation, cleanup or safe-point request refuses the PM replacement. Never bypass those errors, clear slots, edit MoP DB rows, or mutate agent permissions/configuration.

## Dev-slot exit-pending: every daily run, independent of the PM handoff
Rajiv, DM D0AMF0XE6TS thread 1793151634.784279, ts 1793166992.093769: "the daily restart has to set exit pending on all the dev slots as well".
- The checkpoint run arms dev-slot exit-pending right after the snapshot/checkpoint succeeds, BEFORE and independent of the PM effect phase. A deferred, refused or never-reached PM handoff still arms the dev slots. Idempotent per IST day: state key `dev_exit_pending_armed`.
- Dev slots exit only at their own idle safe point (MoP Stop hook / health idle scan); never interrupt a turn; DND slots are skipped.
- The PM is NOT cycled by exit-pending; only the effect phase replaces it via MoP /slots/0/respawn. MoP's flag is global (includes slot 0), so the script arms only when `GET /exit-status` advertises `dev_only`; otherwise it records `blocked_mop_dev_only_scope_missing` and does not arm. The effect phase no longer POSTs /exit-pending.
