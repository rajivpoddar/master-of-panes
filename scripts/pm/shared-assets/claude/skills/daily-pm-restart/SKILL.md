# Daily PM restart

Source: Rajiv, DM D0AMF0XE6TS ts 1793501776.726249: "restart pm pane now. note that mop should wait till the next stop and inject /exit into the pm pane and then the respawn command with the continuation prompt." Ts 1793502261.099499: "exit pending already has the exit injection logic at the next stop. just enabling it should work". Ts 1793502605.714159: "note that all dev slots have to be restarted after pm restart".

1. Run `~/.claude/scripts/pm/daily-pm-restart.sh` once. It snapshots the canonical obligations, slots and PRs into the dated 0400 resume file, updates MEMORY.md, and arms MoP `POST /exit-pending` with `enabled: true`, `pm_only: true`, and the saved `continuation_prompt`. `--dry-run` is read-only. If MoP does not advertise PM-only support, no global or dev-only fallback is allowed.
2. MoP opens ONE `pm_save_handoff` obligation (variant `exit`; Rajiv DM D0AMF0XE6TS thread 1793731816.594829, ts 1793752982.460979: "We should implement the pm exit pending the same way. The additional step here will be to stop all subagents after save handoff"). PM, in order: (a) saves the handoff, updating `memory/MEMORY-session-handoff-current.md` and `data/pm-continuation-note.md` (the same two files the clear flow watches; the dated resume prompt is the continuation payload, not the save signal); (b) stops ALL running background agents/tasks with TaskStop; (c) ends the turn. There is no ACK (Rajiv DM D0AMF0XE6TS thread 1793754554.496299, ts 1793758450.451269: "remove the acks and the gates. as long all subgents are stopped and resume point is saved, it should work."). Until the save, nothing is blocked: the exit stays pending under the normal obligation cadence. Each PM Stop runs at most ONE maintenance command: a latched clear keeps priority, otherwise a ready exit wins and the clear waits.
3. PM stays active with normal input and tool delivery. At the next Stop after the save, MoP attempts `/exit` once; a busy pane or new input does not refuse it (Claude Code queues `/exit` mid-turn). A refused episode never blocks a fresh `pm_only` request; its existing watchdog respawns PM using `RESTART_COMMANDS[0]` (`launch-pm-cliproxy.sh --continue`) and sends the saved continuation instead of literal `continue`. Never respawn the pane directly or invoke `--complete-on-idle`; that legacy entry point performs no replacement.
4. Only after PM is back and its continuation is delivered does MoP reset dev cycle flags and arm `dev_only`. Each dev exits at its own next Stop. DND slots are skipped; never interrupt a turn or manually clear/reassign a slot.
5. The new PM reads the resume file and canonical ledger, reconciles background-agent owners with live work, and relaunches only stopped agents with open work. Do not duplicate running or completed agents or invent a missing task packet. Preserve evidence, branches and ownership.
6. After recovery, send one line to Rajiv's DM `D0AMF0XE6TS` with the resume path and blocked relaunches through the existing Slack sender. Use a unique scratch input file. `ALREADY_REQUESTED` means reconcile the retained request, not force another restart.

The script is locked and durably checkpointed per IST date. It records intent before the HTTP request so an accepted arm with a lost response cannot automatically reset the cycle flags. Reconcile uncertain requests using `/exit-status`, pane state and the saved state file; never blindly retry. Logs are `/tmp/daily-pm-restart-<date>.log`; state is `~/.claude/state/daily-pm-restart-<date>.json`.

No maintenance mode, PM input/tool gating, idle-timer delay or tracked-tool-accounting dependency is introduced. The UserPromptSubmit hook chain is unchanged. Do not edit MoP DB rows or mutate agent permissions/configuration.
