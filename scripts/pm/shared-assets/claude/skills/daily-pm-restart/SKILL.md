# Daily PM restart

1. While processing this skill, run `~/.claude/scripts/pm/daily-pm-restart.sh` once. This is CHECKPOINT ONLY: it snapshots canonical obligations, slots and PRs into the dated 0400 resume file, updates MEMORY.md, and fsyncs the pending handoff bound to this PM owner/turn. It performs no cleanup, exit-pending request or replacement inside the active PM/helper tree. Then return from this skill/turn; do not run more tools, poll, launch a detached helper or invoke `--complete-on-idle` yourself. The EXISTING MoP debounced Stop/idle boundary owns that continuation outside Claude's tree, only with no queued work. It runs guarded cleanup, arms safe-point dev exits, and performs the pinned PM replacement once. Use `--dry-run` for read-only inspection. Never interrupt or respawn a dev pane.
2. The new PM reads the resume file and current ledger, reconciles each listed background-agent owner with live work, and relaunches only stopped agents that still have open work. Preserve task evidence, branches and ownership; a person or slot owner is not an agent type. Do not duplicate a running or completed agent. If the original agent packet is unavailable, record that precise blocker rather than inventing its task.
3. After recovery, post ONE line to Rajiv's DM `D0AMF0XE6TS` with the resume path and any blocked relaunches using the existing slack-send.sh and a unique scratch input file. An idempotent `ALREADY_REQUESTED` result means finish recovery from the saved file, not force another restart.

The script is locked and durably checkpointed per IST date. Busy checkpointing pins the Claude owner without treating its own Bash/Python/ps descendants as quiescent; only the later effect phase requires proven idle, no queued work, an empty composer and NO tool descendants. That phase binds immutable pane/session/PID/process birth/checkout plus the saved SessionStart/UserPromptSubmit and work-event history; only the requesting Bash's completion and Stop may follow the checkpoint. A new prompt, successor or intervening tool prevents the old handoff. Full fresh identity/work checks remain after cleanup and immediately before replacement. The final tmux command also compares immutable pane/session/PID and targets that pane ID, not a numeric address. A fsynced attempted replacement is permanent even after timeout, lost response or exception: reconcile the pane and retained state; never clear intent or issue another kill automatically. Logs are `/tmp/daily-pm-restart-<date>.log`; state is `~/.claude/state/daily-pm-restart-<date>.json`. A failed snapshot, pointer validation, cleanup or safe-point request refuses the PM replacement. Never bypass those errors, clear slots, edit MoP DB rows, or mutate agent permissions/configuration.
